# Quantile protocol in the main camera

Text and music servers advertise `"protocol": "quantile-v2"` on live measures.
The normal UI selects its unary Connect client from that metadata. Old live
manifests and recorded `.pb` snapshots continue using v1. Comparisons can use
different v2 server URLs; label meanings and paths must agree, while opaque
node handles remain specific to each endpoint.

Use the normal `bun run dev` and `uv run export/serve.py` commands. The same
camera, token labels, hover/path inspector, unit switch, keyboard controls,
and music reading/roll operate on the progressively refined scene. V2 slots
stay in ascending token ID order, matching the wire CDF. Anchors remember ID
boundaries as well as transient slot indices, keeping the viewed edge fixed
when an unresolved range splits. Q refinement never reorders P's rows.
The ancestor walk still avoids absolute root-CDF coordinates at deep zoom.

## Wire contract

`proto/natlas/v2/natlas.proto` defines the unary endpoint
`POST /{measure}/natlas.v2.Natlas/Quantile`, with `application/proto` bodies.
Both bindings are generated by `bun run proto`.

Unset node means root. Otherwise name a child by its parent's server-local
handle and its shared branch ID. Prefix bytes select a radix-256 window of
that node's original CDF. Empty selects [0,1); appending a byte selects one
of its 256 subwindows, without conditioning or changing nodes.

A response contains the node handle, first inverse-CDF ID, and 256 packed
unsigned ID deltas including the right endpoint. For prefix A of d bytes,
boundary j is (256A+j)/256^(d+1). At u<1 return the first ID with cumulative
mass greater than u; at u=1 the sentinel is vocabulary size. Zero-weight IDs
are skipped, so deltas count ID positions rather than positive-mass branches.
Terminal nodes have no deltas.

Replies describe a fixed measure. The client validates cardinality, ID ranges,
child/parent agreement and repeated pages. Pages are cached by node, measure
and prefix. Forgotten handles are recovered by naming ancestors again.

## Precision and caching

`export/quantile.py` converts log weights into binary64 significands with
integer exponents. Normalization and cumulative sums use integers, preserving
tails that would underflow in `exp(logp)` and avoiding rounded float CDFs near
1. Input logits retain their original precision: this does not claim exact
real-valued exponentiation. Query coordinates are compared as exact dyadic
rationals.

Current resource limits are 1024 prefix bytes and a log-weight range of 16384
bits. Exceeding either returns an explicit error. Each measure caches CDFs in
LRU order under a 1 GiB estimated storage budget, including Python integer
storage, configurable through `Service(cache_bytes=...)`. A single CDF larger
than the budget stays cached so subsequent pages can reuse it. Handle
identities depend on paths rather than registration
order, avoiding accidental reuse for different paths after a restart.

## Asynchronous inference

`export/inference.py` separates request handling from model execution. Handles,
CDF caches and pending CDF builds belong to the server's event loop. A cached
page can return while another node is being inferred. CDF construction, page
generation and legacy listing/encoding run on CPU threads independently of
the model executor.

Both v1 and v2 submit immutable `Job(measure, path)` values to one shared
worker. Paths are relative to the server's configured model root; jobs contain
no HTTP requests, opaque node handles, horizons or CDF prefixes. Duplicate
outstanding jobs share a result. The default capacity is 64 distinct queued
and running jobs; new jobs beyond it get Connect `resource_exhausted` (HTTP
429 for v2). Cache hits and duplicate waiters do not consume another slot.

The backend contract is asynchronous `evaluate(tuple[Job, ...])`, returning
one log-weight tuple or exception per job, keyed by the original job. Results
may arrive in a different order; missing or unexpected job keys reject the
batch. A backend is bound to one fixed set of measures. This is the extension
point for native batching or remote execution. The current `LocalBackend`
owns one dedicated thread and evaluates jobs serially, preserving stateful
model/KV-cache access. The worker defaults to batches of one; a larger
`batch_size` drains already queued jobs without adding a batching delay.
`app(..., backend=..., capacity=..., batch_size=...)` configures this boundary.

Cancelling a worker waiter leaves other waiters intact. An abandoned queued
job is removed; running inference finishes. V2 CDF builds deliberately keep
their worker waiter alive after an HTTP cancellation, completing and caching
the accepted distribution for other pages. Failed builds are removed so they
can be retried. Starlette's lifespan starts the worker and, on shutdown,
rejects queued inference, finishes the active batch, closes the backend and
settles outstanding CDF and legacy listing builds. The inference queue never
holds cache locks.

## Sampling, fetching and rasterization

A page partitions its window into 256 equal-mass bins. Matching endpoint IDs
certify a homogeneous bin; differing endpoints leave token ownership unknown.
The client stores bounds on shared cumulative boundaries F(id) as exact
base-256 rationals. F(0)=0 and F(V)=1 are known from normalization. Subtracting
aligned integers gives mass bounds for a token or an entire ID range.

`QuantileFetched` contains CDF evidence, separate from a v1 `RankedFetched`
listing. It does not publish guessed token weights with zero leftover.
`RadixCDF.partition()` produces disjoint whole-ID regions. A token receives a
named region only after some positive mass is certified; gaps remain explicit
unresolved ranges. The shared boundary midpoints provide a representative
partition for navigation. Pinning a travel token never renormalizes neighbors.

Hatched regions show unresolved ownership or subpixel collections. Their
horizontal span is a placeholder, not a measured surprisal or entropy area.
Named tokens expose P and Q intervals, including in P=Q. The same CDF
representative supplies both height and width in P=Q. Hatched edge bands show
local cumulative-boundary and width uncertainty. Ancestor placement and scale
still use representatives: these local bands are not a certified envelope for
the whole nested scene, and the inspector states that limitation.

Node entropy readouts bound each group's contribution between -r ln r and
r ln(m/r), optimizing over its mass interval, where m is the number of IDs in
the group. Cross-entropy can have an infinite upper bound while Q or ownership
is unresolved. No uniform-within-group assumption supplies a point statistic.

P refinement prioritizes unresolved bins touching visible IDs or ID ranges,
down to half a screen pixel vertically per bin. A CDF window relative to the
camera's local ID boundary excludes offscreen bins even inside a large unnamed
range; rational differences avoid float cancellation near CDF 1. This is a
local budget, not a whole-path pixel-error guarantee. Explicit prompt/travel
IDs have their P boundaries refined even when initial pages missed them.

Fetching a child's distribution requires its parent-CDF lower mass bound to
support at least two screen pixels of height. If the bounds straddle that
cutoff, the scheduler spends the continuation's visible-area priority on
refining the parent endpoints first. A coarse sample assigned a whole bin
therefore cannot launch inference for a token that later resolves below the
cutoff. Tokens already supported by the bounds can expand while the rest of
the parent is still being refined.

For each visible token, q endpoints are bracketed in ID order. Subtracting
aligned BigInts gives probability bounds [L,U], hence width bounds
[-ln U,-ln L]. At k pixels per nat, uncertainty is k ln(U/L). Each edge gets
0.25/depth² pixels, whose sum along a path is below half a pixel. Refinement
stops sooner if the width lower bound extends past the viewport. Widths stay
in log space, including below floating-point probability range.

The scheduler alternates p geometry and q precision, fetching one new page
per task with bounded concurrency. Nodes are prioritized by the sum of their
visible box areas: probability height relative to the view times width in
nats, clipping both dimensions to the viewport. Unfetched children use the
visible area their continuations could occupy to the right of their own box.
An ancestor whose boxes are offscreen remains eligible for dependency work
with zero visible-area priority; its full projected height does not promote
it ahead of visible refinement. Pixel precision budgets remain separate from
this ordering.

Replies refill fetch capacity independently of animation frames. Before each
batch, current view geometry is recomputed
using a camera copy, so new evidence affects the next requests
without moving the displayed camera between paints. The pump yields between
batches and retries failures after backoff, even without further input. A
dataset switch retires its old scheduler. Drawing and canvas resizing stay in
the same animation frame.

The scheduler also requests ancestor q endpoints when those boxes lie left of
the viewport, since they place visible descendants.
Tiny adjacent v2 boxes form a hatched aggregate without an invented average
width. Legacy v1 retains its ranked listings and tail rendering.

## Validation

For a deterministic ID-order preview with sparse ranges, peaks, P/Q reversal,
and tiny-token travel, build into a separate directory and run:

```sh
bun build ./index.html --outdir /tmp/natlas-id-order-build
python3 tests/id_order_fixture.py --static /tmp/natlas-id-order-build
# Open http://127.0.0.1:8423/?server=http://127.0.0.1:8423/
```

To compare independent servers, start another instance with `--port 8424`,
and pass `--peer http://127.0.0.1:8424/` to the first. `--delay 0.03` makes
progressive refinement easier to observe. Neither fixture uses model inference.

```sh
bun test
bun run build
python3 -m unittest discover -s tests -p '*_test.py'
```

Python tests require numpy, protobuf, starlette and its test-client dependency
(httpx or httpx2, depending on the installed Starlette). They exercise CDF
precision, masks, generated protobuf exchange, error statuses, the real unary
route and inference-worker concurrency. Event-gated tests verify cached-page
responses during blocked inference, duplicate sharing, bounded admission,
cancellation, per-measure identity, batch result matching and shutdown without
loading a model. TypeScript tests cover indistinguishable coarse distributions,
shared boundary certificates, tiny probabilities near CDF 1, stable ID anchors,
visible-window refinement, coherent P=Q geometry, entropy/cross-entropy bounds,
prompt IDs and handle recovery, alongside the existing v1 and deep camera tests.

To test the main UI with the Qwen NPZ ZIP, without model/GPU inference:

```sh
bun run build
python3 tests/quantile_fixture.py --samples /path/to/natlas-samples.zip --static dist
# Open http://localhost:8423/?server=http://localhost:8423
```

The fixture uses `serve.app` with the supplied recordings as inference output.
Missing continuations are finite-snapshot leaves rather than model EOS.
`tests/quantile-camera.cjs` exercises the UI with Playwright against the fixture
(root, double-click, q switch, swap, depth, scale, prompt and drag). Set
`CHROMIUM_PATH` if necessary. GPU model execution is not part of this fixture.
